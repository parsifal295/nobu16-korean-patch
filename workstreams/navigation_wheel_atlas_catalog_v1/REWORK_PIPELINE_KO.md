# 네비게이션 휠 일관 재작업 파이프라인 제안

## 목표

현재 방식의 핵심 문제는 아이콘·휠 몸체·한국어 글자가 한 장으로 합쳐진 생성 이미지라는 점이다. 전체 이미지를 원본 바운딩 박스에 맞추면 글자 길이나 생성 여백에 따라 몸체까지 함께 축소된다. 실제 감사에서도 기본판 세부 휠 684개가 모두 원본 대비 5% 넘게 달랐다.

재작업의 원칙은 다음 한 문장으로 정리된다.

> 일본어 원본의 휠 몸체와 아이콘 및 런타임 기하를 보존하고, 번역 글자만 독립된 결정론적 레이어로 생성한다.

## 1. 계약 고정

`navigation_wheel_catalog_v1.json`을 유일한 배치 원장으로 사용한다.

- 경로 4개, 배치 900개가 모두 존재해야 한다.
- 레코드 번호, 논리 셀, 실제 클립 영역, BC3 블록 영역을 변경 금지 계약으로 둔다.
- 기본판 46개 고유 세부 자산 → 57개 그룹 매핑을 유지한다.
- PK는 저/고해상도 셀이 정확한 2배가 아니므로 경로별 기하 계약을 따로 둔다.
- 6개 상태의 순서와 원본 색·명도·선택 표시를 원본에서 직접 고정한다.

## 2. 원본을 레이어로 분해

각 고유 항목의 일본어 원본 6상태에서 다음 레이어를 만든다.

1. `body`: 꽃잎/원형 휠 몸체와 테두리
2. `icon`: 명령 의미를 나타내는 중앙 그림
3. `native_label_mask`: 일본어 글자와 외곽선·그림자 마스크
4. `state_style`: 상태별 몸체 팔레트, 글자 채움, 외곽선, 그림자, 선택 화살표

일본어 글자를 지운 자리의 몸체는 같은 상태의 대칭·인접 픽셀 또는 다른 상태의 공통 몸체 레이어로 복원한다. ImageGen으로 완성 휠을 다시 만들지 않는다. 자동 분리가 애매한 항목만 수동 마스크 검수를 거친다.

결과는 투명 PNG 하나가 아니라 원본 SHA에 연결된 레이어 묶음과 마스크 통계로 남긴다.

## 3. 타이포그래피 규격

한글 렌더링은 다음 값을 명시한 벡터/텍스트 규격에서만 수행한다.

- 폰트 파일과 SHA-256
- 글자 무게와 렌더러 버전
- 기준선, 광학 중심, 목표 잉크 높이
- 자간, 장평 허용 범위
- 외곽선·그림자 두께와 오프셋
- 좌우 안전 여백, 몸체 아래쪽과의 최소 간격

핵심은 문자열 길이에 따라 휠 전체를 줄이지 않는 것이다.

- 휠 몸체와 아이콘 크기는 항상 원본 100%로 고정한다.
- 먼저 동일한 목표 잉크 높이로 한글을 렌더링한다.
- 긴 문자열은 제한된 자간 조정 → 제한된 장평 조정 순으로 맞춘다.
- 그래도 넘는 경우에만 사전에 정의한 `compact` 등급을 사용한다.
- 폰트 크기 축소는 계열별 임의 판단이 아니라 명시된 등급 하나로만 허용한다.
- 두 글자·세 글자·네 글자의 시각 무게가 비슷하도록 실제 잉크 면적과 기준선을 함께 측정한다.

권장 초기 허용치는 다음과 같다.

- 몸체/아이콘 원본 대비 가로·세로: 0.98~1.02
- 글자 잉크 높이 목표 대비: ±2%
- 기준선: 저해상도 ±1px, 고해상도 ±2px
- 상태 간 글자 바운딩 박스 변화: 저해상도 ±1px, 고해상도 ±2px
- 좌우 안전 여백: 저해상도 2px 이상, 고해상도 4px 이상

이 값은 대표 항목 실게임 파일럿에서 확정한 뒤 전 항목에 적용한다.

## 4. 해상도 생성 정책

### 기본판

기본판은 메타데이터 코어와 논리 셀의 **크기**가 정확히 2배다. 아틀라스 안의 `(x, y)` 패킹 위치는 서로 독립적이므로 반드시 각 해상도의 카탈로그 좌표를 사용한다. 하나의 정규화된 벡터/레이어 규격에서 1×와 2×를 각각 렌더링하거나, 2× 마스터를 만든 뒤 premultiplied-alpha Lanczos로 1×를 내린다. 어느 쪽이든 몸체·아이콘·기준선의 2배 대응을 자동 검사한다.

### PK

PK는 논리 셀이 정확한 2배가 아니다.

- 세부 휠: 104×96 → 200×184
- 주 휠: 104×96 → 204×188

따라서 캔버스를 단순 2배 축소·확대하지 않는다. `body/icon/label`의 정규화 좌표를 각 경로의 메타데이터 코어에 투영하고, 경로별 원본 기준선과 안전 여백을 적용한다. 저·고해상도 결과는 같은 의미 규격을 공유하지만 서로 별도의 네이티브 합성 결과다.

모든 리사이즈는 premultiplied alpha로 처리해 투명 경계의 검은 테두리와 색 번짐을 막는다.

## 5. 상태 스트립 생성

각 고유 명령은 한 번만 조립하고 6상태를 상태 템플릿으로 파생한다.

- 상태마다 독립적으로 이미지를 생성하지 않는다.
- 몸체와 아이콘의 위치·크기는 6상태에서 동일해야 한다.
- 상태별 차이는 팔레트, 밝기, 글자 색, 선택 장식처럼 원본이 실제로 바꾸는 값으로 제한한다.
- 중복 그룹은 동일한 결과 바이트를 재사용한다.

이 방식이면 `출진` 네 위치, `군개발` 세 위치처럼 같은 명령의 크기가 화면마다 달라지는 것을 구조적으로 막을 수 있다.

## 6. 아틀라스 합성과 인코딩

1. 카탈로그에서 대상 레코드와 논리 셀을 읽는다.
2. 원본 글자 마스크만 제거한다.
3. 보존한 원본 몸체·아이콘 위에 한국어 글자 레이어를 합성한다.
4. 새/옛 알파 마스크가 닿는 BC3 4×4 블록만 다시 인코딩한다.
5. 선택되지 않은 BC3 블록, G1T 바이트, 중첩 LINK 엔트리, 바깥 LINK 엔트리는 바이트 단위로 보존한다.
6. 디코딩 왕복 후 계획된 블록 밖의 변경이 0인지 검사한다.

## 7. 자동 게이트

빌드는 다음 조건을 모두 만족해야 성공한다.

- 카탈로그 커버리지: 4경로, 900배치, 누락·중복 0
- 모든 논리 셀과 BC3 블록이 아틀라스 범위 안에 있음
- 원본 몸체/아이콘 바운딩 박스 허용치 통과
- 글자 잉크 높이·기준선·안전 여백 통과
- 같은 고유 명령의 중복 그룹이 픽셀 동일
- 6상태의 몸체/아이콘 기하가 허용치 안에서 동일
- 기본판 저/고해상도 대응이 2배 계약 통과
- PK 저/고해상도 대응이 경로별 네이티브 계약 통과
- 변경 허용 블록 밖 바이트 변화 0
- 동일 입력으로 두 번 빌드한 산출물 SHA-256 동일
- 원본/한국어, 1×/2×, 6상태 접촉 시트 생성

현재의 상단 몸체/아이콘 프록시와 하단 글자대역 프록시는 발견용 게이트로만 쓴다. 새 파이프라인에서는 몸체·아이콘·글자 레이어가 독립되므로 각 레이어의 실제 마스크 바운딩 박스와 글자 잉크 면적을 직접 측정한다.

## 8. 파일럿 순서

전량 교체 전에 편차와 문자열 길이를 대표하는 다음 항목으로 파일럿을 만든다.

- 심한 축소: `입성`, `성정보`, `호출`, `주명`
- 긴 글자: `합전정보`, `원군요청`, `성하시설`, `영지계책`, `공략목표`
- PK 긴 글자: `보급거점`, `방어거점`
- 주 휠: `군평정`, `군사`, `광역`

파일럿에서 폰트, 잉크 높이, 기준선, 외곽선과 장평 등급을 확정한 뒤 46개 기본판 고유 세부 자산, 5개 주 휠, 12개 PK 세부 자산, 1개 PK 주 휠 순으로 확장한다.

## 9. 실게임 QA와 배포

정적 검증이 끝난 최종 후보만 실게임과 Steam에 적용한다.

권장 QA 해상도:

- 1280×720: 저해상도 경로
- 1920×1080: 경로 전환 경계와 일반 사용
- 3840×2160: 고해상도 경로

해상도를 바꾼 뒤에는 반드시 `NOBU16PK.exe`를 완전히 종료하고 다시 실행한다. 각 캡처에 선택 해상도와 완전 재시작 여부를 기록한다. 프로세스 재시작 전 이미지는 아틀라스 캐시 때문에 적용 실패의 증거로 사용하지 않는다.

검수 승인 뒤에만 v0.94 후속 리소스 번들을 만들고, 격리 fixture 적용/복원 → ZIP 해시 검증 → Steam 백업 → 최종 배포 순서로 진행한다.
