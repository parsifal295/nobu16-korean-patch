# 일반 버튼 비생성형 레이어 재작업 파이프라인 v1

## 목표와 고정 선택

휠 재작업과 같은 원칙으로 일반 버튼 266개를 다시 만든다. 완성 이미지를 확대하거나 새로 생성하지 않고, 순정 버튼의 몸체·아이콘·상태 효과를 원래 크기로 보존한 뒤 글자 레이어만 교체한다.

- 글꼴: 사용자 선택 B, `SeoulHangang ExtraBold`
- 고정 파일: `SeoulHangangEB.ttf`
- SHA-256: `60D6A471E9A14F4BA563612D2577B9B6CCB2D1C599A69191B3F9F82EF80A19D1`
- Imagen, ImageGen, 생성형 채움, 생성형 인페인팅: 사용 금지
- 패처에는 폰트 파일이 아니라 고정 입력으로 래스터화한 결과만 포함

휠의 23px 글자 높이는 휠 전용 후보 조건이므로 버튼에 그대로 복사하지 않는다. 버튼은 아래 파일럿에서 순정 글자의 잉크 높이·기준선·안전 폭을 상태별로 측정해 별도 계약을 확정한다.

## 1. 입력 동결

`ordinary_button_catalog_v1.json`의 순정 아카이브 해시와 다섯 경로를 빌드 입력 계약으로 사용한다. JP를 기준으로 EN·SC·TC 순정 아틀라스를 추가 공여본으로 고정하되, 이미 수정된 라이브 파일은 공여본으로 쓰지 않는다.

각 배치는 다음 키로 추적한다.

`route / family / group / name / state`

좌표는 CSV의 `processing_rect`와 `atlas_clip_rect`를 사용한다. 저해상도 좌표를 2배 해 고해상도 위치로 추정하지 않는다.

## 2. 상태 정렬과 원본 레이어 분리

한 레이블의 6상태를 다음 레이어로 분리한다.

1. `body`: 프레임, 재질, 그라데이션, 알파 실루엣
2. `state_fx`: 선택광, 비활성화, 청색·백색 상태 효과
3. `icon`: 체크, X, 화살표 등 의미 아이콘
4. `source_label`: 제거할 일본어 글자
5. `protected`: 어떤 처리에서도 바뀌면 안 되는 픽셀

저해상도 상태는 카탈로그의 배경 특징 분류 결과로 먼저 1→6에 정렬한다. 고해상도는 검증된 연속 6상태 순서를 사용한다. 언어판끼리 상태 순서가 다르면 동일한 무문자 배경 띠와 아이콘 특징으로 재정렬한다.

아이콘 보호 마스크는 레이블별로 별도 관리한다. 특히 `닫기`, `승인`, `부인`, `거절`, `뒤로`, `예/아니오`, `다음`은 글자와 아이콘을 한 마스크로 묶지 않는다.

## 3. 일본어 글자 제거

글자 제거는 생성 없이 실제 순정 공여 픽셀만 사용한다.

1. JP/EN/SC/TC에서 서로 다른 글자 잉크를 비교해 공통 몸체 픽셀을 찾는다.
2. 상태별 `source_label` 핵심 마스크를 만들고 외곽선·안티앨리어싱 꼬리를 단계적으로 포함한다.
3. 같은 좌표에 글자가 없는 순정 언어판의 premultiplied-RGBA 중앙값을 복사한다.
4. 모든 언어판에서 가려진 소수 픽셀은 같은 상태·같은 재질 영역의 가장 가까운 **실제 공여 픽셀**을 복사한다.
5. 보간, 생성형 인페인팅, 몸체 재도색은 하지 않는다.

결과는 `clean_body + state_fx + icon`이며, 제거 마스크와 보호 마스크 밖 RGBA가 JP 순정과 같은지 바이트 단위로 검사한다.

## 4. B 글자 레이어 렌더링

글자는 투명 레이어로 독립 생성한다.

- 기본값은 장평을 바꾸지 않고 SeoulHangang ExtraBold의 원래 비율을 유지한다.
- 저해상도는 8배, 고해상도는 4배 오버샘플 후 premultiplied-alpha 축소를 기본값으로 한다.
- 레이블의 광학 중심, 기준선, 외곽선, 색은 각 순정 상태에서 측정한다.
- 같은 레이블의 6상태는 글자 기하를 공유하고 팔레트·외곽 효과만 상태별로 바꾼다.
- `전부해방`, `건너뛰기`, `재교섭`처럼 긴 문자열은 글자 크기를 임의 축소하지 않는다. 먼저 안전 폭을 측정하고, 필요한 경우 자간 등급을 사전에 정한 제한 안에서만 조정한다.
- `전체승인`은 사용자 지시로 확정한 예외다. 공백 없이 표기하고, 긴 표기 전용 Compact 잉크 높이 26px/52px, 장평 80%, 기본 자간 `-0.035em`, 중심 `(117,41)`/`(227,76)`을 사용한다. 순정 체크–`全` 코어 최단거리(저 8.485281px/고 16.970562px)와 새 체크–`전` 거리를 0.75px 이내로 맞춘다. 모든 상태 글자 경계는 저해상도 `x=74..178`, 고해상도 `x=140..338` 내부 레인을 통과해야 하며 체크 보호 마스크와의 겹침 및 보호 픽셀 차이는 0이어야 한다.

저·고해상도는 같은 벡터 글자 계약에서 각각 네이티브 캔버스로 직접 래스터화한다. 저해상도 결과를 확대하거나 고해상도 결과를 축소해 재사용하지 않는다.

## 5. 합성과 압축 블록 교체

합성 순서는 `clean_body → state_fx → icon → B label`이다.

- BC3 경로는 각 행의 `bc_block_rect`와 교차하는 블록만 다시 인코딩한다.
- BC7 `전체승인`은 검증된 저해상도 192×88 셀과 고해상도 368×160 셀만 처리하고, 고정된 BC7 인코더 버전과 설정을 사용한다.
- 처리 사각형 밖 G1T 바이트, 선택하지 않은 텍스처, 중첩 LINK 엔트리, 바깥 LINK 엔트리는 바이트 단위로 보존한다.
- 같은 입력으로 두 번 빌드한 결과의 SHA-256이 같아야 한다.

`개전` 고해상도는 상태 1과 상태 2~7의 네이티브 크기가 다르므로 상태별 처리 사각형을 그대로 사용한다. `전체승인` 저해상도 좌표는 고해상도 좌표를 절반으로 나누지 않고 순정 저해상도 아틀라스에서 독립 검출한 192×88 셀을 사용한다.

## 6. 파일럿

전량 처리 전에 다음 8개로 글자 계약과 마스크 품질을 확정한다.

- 아이콘 보호: `닫기`, `승인`, `뒤로`
- 짧은 확인 계열: `예`, `아니오`
- 긴 문자열: `전부해방`, `건너뛰기`
- 특수 경로: `개전`, `전체승인`

파일럿 접촉 시트는 원본/클린 몸체/B 합성, 1×/고해상도, 모든 상태를 같은 행에 놓는다. 사용자 승인 후 표준 20종, `개전`, `전체승인` 순으로 확장한다.

## 7. 자동 검증

필수 게이트는 다음과 같다.

- 5경로, 22논리 그룹, 266배치 누락 0
- 표준 버튼 20종의 상태 1→6 매핑 유지
- 저해상도 표준 아트워크 180×79, 고해상도 360×158 유지
- 표준 처리 캔버스 192×88 / 376×168 유지
- 아이콘·몸체 보호 마스크 밖 변경 픽셀 0
- 새 글자 레이어가 레이블 안전 영역을 벗어난 픽셀 0
- 선택하지 않은 BC3/BC7 블록 변경 0
- 관련 없는 G1T/LINK 바이트 변경 0
- 결정론적 재빌드 해시 일치

## 8. 실게임 QA와 배포

정적 게이트를 통과한 후보만 격리 설치에서 확인한다.

- 1280×720 또는 1280×800: 저해상도 일반 버튼과 `개전`
- 1920×1080: 경로 전환 및 확인 대화상자
- 3840×2160: 고해상도 표준 버튼, `개전`, `전체승인`

해상도를 바꾼 뒤에는 매번 `NOBU16PK.exe`를 완전히 종료하고 다시 실행한다. 결과에 선택 해상도와 완전 재시작 여부를 기록한다. 승인된 최종 후보만 v0.94 패처 번들에 넣고, 그 직전에만 Steam에 적용한다.
