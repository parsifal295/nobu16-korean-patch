# 1920×1080 전투 결과 전공 배지 아틀라스 조사

## 결론

첨부 화면의 전공 1·2·3위 배지 파손은 LINK/G1T 메타데이터나 런타임 UV
테이블 변경이 아니라, 고정 UV가 바라보는 텍스처 내부에서 배지 그림이
이동한 **아틀라스 픽셀 등록(registration) 오류**다.

고해상도 경로는 다음과 같다.

- 파일: `RES_JP_PK_PORT/res_lang_pk_port1.bin`
- outer: `/17`
- nested resource id: `58`
- G1T slot/texture: `/0`, texture `0`
- 형식: PC platform `0x0A`, BC3 `0x5B`, `4096×1024`, texture 1개

순정과 설치본은 위 구조와 G1T payload 앞뒤 바이트가 동일하다. 달라진 것은
BC3 텍스처 payload뿐이다. 따라서 아카이브 인덱스나 G1T 헤더가 틀어진
문제는 아니다.

## 런타임 증거 기록

- 선택 해상도: `1920×1080` (사용자 제보)
- `NOBU16PK.exe` 완전 종료 후 재실행 여부: 확인되지 않음
- 첨부 파일은 업로드 과정에서 `1280×747`로 축소되어 있으므로, 원본 픽셀
  크기 자체는 해상도 판정 근거로 사용하지 않는다.
- 이번 조사는 Steam 설치본을 읽기만 했고 게임 파일을 변경하지 않았다.

프로세스 재시작 여부가 확인되지 않았어도, 아래 순정/설치본 텍스처의 좌표
불일치가 첨부 화면의 파편 모양을 직접 설명하므로 정적 원인 판정에는 영향이
없다. 수정 후보의 실게임 합격 판정에는 반드시 완전 종료·재실행이 필요하다.

## 전공 배지 위치 불일치

알파 임계값 32로 연결 성분 bbox를 측정했다.

| 배지 | 순정 bbox | 설치본 bbox | 좌상단 이동 |
| --- | --- | --- | --- |
| 전공 1위 | `[2960,400,3344,480]` | `[2984,383,3364,459]` | `(+24,-17)` |
| 전공 2위 | `[2982,500,3322,572]` | `[3002,485,3346,549]` | `(+20,-15)` |
| 전공 3위 | `[3686,644,4026,716]` | `[3693,625,4029,688]` | `(+7,-19)` |

런타임 sprite UV는 순정 배치 사각형을 계속 사용한다. 설치본 그림은 위쪽으로
15~19px 이동하고 폭도 달라졌으므로, 순정 UV로 자르면 배지의 일부와 투명
여백이 함께 잡힌다. 첨부 화면에서 1위 배지가 적장 초상 위·아래의 노란
파편으로 나뉘고, 중앙 하단 배지들이 작은 조각으로 보이는 현상과 일치한다.

## 유입 경로

문제 `/17` payload가 처음 확인되는 전체 후보는 다음이다.

- `tmp/steam_jp_port_imagegen_v1/final_port1_002/.../res_lang_pk_port1.bin`
- 전체 SHA-256: `3F834823…AE976`
- outer `/17`: `933E3C41…4E7FF91`
- texture payload: `8A76725B…D699AC5`

이후 wheel/system 후보와 v0.10.1 이후 릴리스는 `/17`을 그대로 보존했다.
2026-07-22 추가 콘텐츠 고해상도 변경은 `/18`만 바꾸었으며 `/17`은
byte-identical이다. 따라서 최근 추가 콘텐츠 패치는 원인이 아니다.

원래 안전한 `steam_jp_military_overlay_v1` 작업은 배경 보존이 미해결된 전공
1·2·3위 배지를 `audit-only`로 두었다. 뒤의 ImageGen 합성 경로가 이 제한을
깨고 배지 사각형까지 교체했다.

문제를 만든 처리 순서는 다음과 같다.

1. `prepare_port1_imagegen_edits.py`가 `1774×887` ImageGen 결과에서
   content bbox `[0,134,1774,747]`를 자른다.
2. 잘린 `1774×613` 전체를 `4096×1024`로 비등방 확대한다.
3. `build_steam_jp_port_imagegen_v1.py`가 순정 native 사각형을 투명하게
   지운 뒤 이 확대본의 같은 좌표를 합성한다.
4. ImageGen 결과 안의 배지는 native 좌표에 고정되어 있지 않으므로, 확대본의
   배지가 위 표처럼 이동·변형된 채 들어간다.

## 저해상도 경로의 별도 문제

저해상도 경로는 `RES_JP/res_lang.bin /12/0`, BC3 `2048×512`다.
`build_low_from_reviewed_high_imagegen_v1.py`는 고해상도 `/17` 전체를 단순
1/2 축소해 `/12`에 넣었다.

하지만 PC 저해상도와 고해상도 아틀라스는 캔버스 크기만 1:2일 뿐 내부 sprite
패킹은 1:2 대응이 아니다. 예를 들어 순정 저해상도 전공 1위 bbox는
`[1082,254,1274,294]`인데, 순정 고해상도 bbox를 반으로 나누면
`[1480,200,1672,240]`이다. 현재 저해상도 설치본 전공 1위는 실제로
`[1492,191,1682,230]`에 있어 잘못된 고해상도 반축소 위치를 따른다.

따라서 저해상도 `/12`는 고해상도 수정본을 다시 축소해서 만들면 안 되며,
저해상도 순정 아틀라스의 독립 좌표계에서 별도로 재구성해야 한다.

## 기존 QA의 누락

`audit_active_image_goal_v1.py`는 outer/nested/G1T 구조, 해시, 형식, 크기와
후보 일치 여부를 검사하고 전체 아틀라스 PNG를 만들었지만, 순정 sprite별
좌표·bbox 불변 조건은 검사하지 않았다. 그래서 컨테이너 검증은 PASS였지만
고정 UV와 픽셀 위치의 불일치를 잡지 못했다.

## 수정 후보의 합격 조건

1. 고해상도 `/17/0`은 PC 순정 `4096×1024`를 기준으로 다시 만든다.
2. 전공 1·2·3위 배지 배경과 장식은 순정 native 좌표를 보존한다.
3. 한글은 검증된 text-only alpha/mask로만 고정 사각형 안에 렌더링한다.
4. 저해상도 `/12/0`은 PC 순정 `2048×512`를 기준으로 독립 재구성한다.
5. 비대상 BC3 block은 순정 또는 승인된 직전 기준선과 byte-identical이어야 한다.
6. sprite별 expected bbox/UV crop 회귀 검사를 추가한다.
7. Steam에는 중간 후보를 적용하지 않는다.
8. 릴리스 승인 직전 실게임에 적용한 뒤 `NOBU16PK.exe`를 완전히 종료·재실행하고
   `1280×720`, `1920×1080`, 필요 시 `3840×2160`에서 같은 전투 결과 화면을
   확인한다. 각 결과에 선택 해상도와 완전 재시작 여부를 기록한다.
