# 여성 무장 이름 전수 감사 v2

> 최신 정적 후보는 기존 안전 수정 11개와 잔여 14개 이름용 18개를 합친
> component 29개다. 57명 재감사에서 모든 후보가 불일치하는 행은 0개가 됐다.
> 확정 조합, 공유 범위와 바이너리 검증 결과는
> [잔여 14개 조합 수정 보고](REMAINING_14_RECORD_COMBINATION_FIX_KO.md)를 따른다.

## 결론

게임의 명시적 `姫武将` 명단 21명에 대해 전체 이름 표시 테이블인
`MSG_PK/*/msgev.bin`을 정적으로 전수 검사했다. 이 테이블의 한국어 행은 21/21
통과했고, 이 감사에서는 게임 설치 파일을 수정하지 않았다. 이는 조합형 UI의 실제
표시까지 자동으로 보장한다는 뜻은 아니며, 그 경로는 아래의 component 수정으로
별도 처리한다.

이 범위는 여성으로 분류될 수 있는 모든 역사 인물을 임의로 추정한 것이 아니라,
게임의 `姫武将` 데이터 명단을 기준으로 한다. 그 밖의 여성 역사 인물까지 포함하는
별도 범위 확장은 이 결과에 섞지 않았다.

## 재현

별도 게임 복사본 또는 읽기 전용으로 사용할 게임 루트를 지정한다. 스크립트는
보고서 출력을 게임 루트 내부에 두는 것을 거부하며, 게임 파일을 쓰지 않는다.

```powershell
python tools/audit_female_officer_names.py `
  --game-root F:\SteamLibrary\steamapps\common\NOBU16 `
  --report workstreams/female_officer_names_audit_v2/public/msgev_female_officer_name_audit.v1.json
```

결과 JSON은 원문 게임 문자열을 넣지 않고, 원문 대조에는 UTF-16LE SHA-256만
사용한다. 한국어 표시명과 ID는 패치 산출물이다.

## 정적 분석 범위와 한계

이번 전수 판정은 목록·이벤트 등에서 쓰이는 전체 이름(`msgev`)의 직접 표시 경로에
대한 것이다. 각 행은 다음을 모두 검사한다.

1. SC/JP/EN `msgev` 컨테이너와 문자열 테이블의 엄격 파싱 및 17,916행 수 일치
2. 공개된 전체 무장 이름 릴리스 recipe의 해당 ID·한국어 출력 일치
3. SC 원문 행의 UTF-16LE SHA-256과 recipe의 원문 해시 일치
4. 현재 JP 한국어 표시명 일치 및 한글/단일 공백 형식 검증

성·이름을 조합하는 편집기 UI의 `msgdata` 경로는 별도다. Ghidra MCP 정적 분석에서는
실행 파일의 조합기가 레코드의 이름 구성 ID를 참조함을 확인했다. 역사 무장 전체의
완전한 `무장 ID → component ID` 대응표는 아직 정적으로 확보되지 않았으므로,
근거 없는 전역 치환은 하지 않는다. 다만 `오시장`처럼 활성 component 조합을
정적으로 재구성할 수 있는 고신뢰 1행은 별도 후보로 수정했다.

[component 수정 기록](COMPONENT_FIX_KO.md)은 62+2083의 `오시장 → 오이치`
재구성 검증과 함께, 영향을 받는 여성 무장 범위를 기록한다.

실행 파일에서 확인한 주소·분기와 `HDATA`가 직접 component 원본이 될 수 없는 이유는
[Ghidra 정적 분석 기록](STATIC_ANALYSIS_GHIDRA_KO.md)에 남겼다.
