# `msgdata` ID 2083 공유 범위 정적 감사

## 결론

활성 `MSG_PK/JP/msgdata.bin`의 ID 2083을 `이치`로 바꾸는 최소 후보는, 정적
무장 이름 카탈로그 `msgev` ID `0..2399` 기준으로 **오이치(ID 404)만 직접 대상**이다.
일반 시장 UI 문구는 별도 ID 24개가 남아 있어 수정되지 않는다.

## 확인 절차

1. Ghidra MCP로 `FUN_1405F40D0 → FUN_1409F9BE0` 조합 경로와 component ID 범위
   `0x0000..0x22DB`를 확인했다.
2. `msgev`의 무장·NPC 이름 카탈로그 2,400행을 정적으로 검색했다. ID 2083과 같은
   원문 component를 포함한 이름은 5행뿐이었다: 241, 252, 404, 1371, 1372.
3. 그중 4행은 ID 2083 대신 이미 더 긴 성 component의 정확한 두-part 분해가 있다.

| `msgev` ID | 정적 component 분해 | ID 2083 필요성 |
|---:|---|---|
| 241 | 573 + 1661 (또는 7764) | 없음 |
| 252 | 572 + 2371 | 없음 |
| 404 | 62 + 2083 | 있음 — `오시장 → 오이치` |
| 1371 | 596 + 2016 | 없음 |
| 1372 | 596 + 2447 | 없음 |

ID 404는 현재 component 재구성값이 실제로 `오시장`인 것을 후보 빌더가 요구하고,
수정 후 `오이치`가 되는지 검증한다. 나머지 4개는 해당 긴 성 component가 현재
한국어 전체 성 표기와 일치하므로 ID 2083을 바꿀 이유가 없다.

## 경계

이 결론은 내장 무장·NPC 이름 카탈로그 범위다. 편집기로 사용자가 임의의 component를
선택하는 기능이 있다면 그 이름도 ID 2083을 선택할 수 있으며, 그때 표기는 `이치`가
된다. 그러나 일반 메시지·시장 UI는 이 ID를 쓰지 않는다. `시장`이 남아 있는 일반
`msgdata` 행 24개는 후보 바이너리에서 byte/text 수준으로 보존됨을 확인했다.
