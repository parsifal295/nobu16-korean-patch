# 여성 무장 이름 조합 재감사 — 11행 후보 후

## 결과

승인된 11행 component 후보를 메모리상 적용한 뒤, 기존 명단 21명과 공용 `姫` component로 추가 확인된 4명을 다시 정적 대조했다.

| 분류 | 인원 |
|---|---:|
| 오이치 관측 조합 정상화 | 1 |
| 모든 정확한 정적 후보가 직접 표기와 일치 | 17 |
| 공백만 차이 | 4 |
| 복수 후보가 서로 달라 보류 | 2 |
| 정확한 SC 두-part 분해 불가 | 1 |

## 네 네 처리

ID 287을 `네`로 바꿨다. 같은 component를 두 번 쓰므로 무공백 formatter에서는 `네네`, 공백 formatter에서는 `네 네`가 된다. 두 표기를 모두 수용하고 끝 공백을 만들 수 있는 `네 `는 사용하지 않는다. 역사 무장 정적 대조에서 ID 287은 1582에만 연결된다.

## 공백만 남는 이름

| 무장 | `msgev` ID | 정적 조합 | 직접 표기 | 앞 component | 역사 무장 정적 공유 |
|---|---:|---|---|---:|---|
| 스와히메 | 1157 | `스와 히메` | `스와히메` | 204 | 8명 |
| 세나히메 | 1170 | `세나 히메` | `세나히메` | 674 | 3명 |

이 앞 component는 다른 이름에서 실제 단어 경계 공백으로도 사용된다. 공백 삭제 후보는 만들지 않았다.

## 레코드 매핑이 필요한 항목

- **오센 (406):** SC 원문이 `msgdata`의 정확한 비어 있지 않은 두-part 조합으로 분해되지 않는다.
- **마츠 (1827):** 정확한 SC 분해가 6개다. 이 중 `(321, 2090)`만 `마츠`로 직접 표기와 일치하지만, 실제 레코드가 이 쌍을 사용한다는 증거는 아직 없다.
- **마쓰히메 (1861):** 정확한 SC 분해가 2개다. 이 중 `(328, 2082)`만 `마쓰히메`로 직접 표기와 일치하지만, 실제 레코드가 이 쌍을 사용한다는 증거는 아직 없다.

Ghidra MCP 확인 결과, `FUN_1405F40D0`은 두 component를 formatter에 넘기고 formatter는 `L"%s\n%s"`, `L"%s %s"`, `L"%s%s"` 형식을 상태에 따라 선택한다. 후행 공백을 일괄 제거하는 경로는 확인되지 않았다. 따라서 위 항목을 해결하려면 실제 무장 레코드의 `+0x08/+0x0A/+0x0C/+0x0E` component ID를 정적으로 복원해야 한다.

## 레코드 경로 추적 결과

조합기 입력 레코드는 `FUN_1405DBD30`이 `id < 0x17F5` 조건에서 DB 포인터 테이블의
`+0xE8 + id*8`로 찾아 돌려준다. 즉 `msgev`의 ID나 `HDATA000.se_n16`의 고정 슬롯을
그대로 조합기 입력으로 사용할 수 없다.

- `HDATA000.se_n16`(헤더 `0x14`, stride `0x386`)의 대상 레코드는 `+0x14`에 무장 ID가
  있지만, 조합기가 읽는 앞쪽 위치에는 `NB16__EDITH_V1` 태그가 있다. 이름 component
  ID가 아니다.
- `EDATA000.st_n16PK_SC` 및 `SCENARIO`/`SCENARIO_PK`는 대상 무장의 component ID 쌍이
  평문 16비트 값으로 들어 있지 않았다. 이 파일들이 원천이 아닐 수 있다는 뜻은 아니며,
  현 상태에서는 역직렬화 형식이 확인되지 않았다는 뜻이다.
- 따라서 현재 정적으로 확정된 것은 **조합기와 DB 조회의 구조**까지다. 오센·마츠·마쓰히메의
  실제 두 ID를 확정하려면 다음 정적 단계에서 DB 초기화/역직렬화 루틴을 추적해야 한다.

이 결과로 추가 `msgdata` 치환은 만들지 않았다. 후보 문자열이 그럴듯하다는 이유만으로
공유 component를 수정하면 다른 무장에 영향을 줄 수 있기 때문이다.

재현용 읽기 전용 감사기는 [audit_female_officer_component_combinations.py](audit_female_officer_component_combinations.py)이며, Steam 설치본은 변경하지 않는다.
