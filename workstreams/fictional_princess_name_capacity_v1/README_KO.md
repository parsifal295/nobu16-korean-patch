# 가상 히메 성명 입력 용량 보정 v1

## 제보와 결론

고바야카와 가문에서 가상 히메의 이름 입력 중 게임이 종료된다는 제보를 정적 분석했다.
제보만으로 입력창을 여는 순간과 `결정`을 누르는 순간 중 정확한 충돌 시점은 확정할
수 없다. 다만 한국어 패치가 물려준 성의 길이와 일본어 실행 파일에 남아 있던 세 개의
고정 용량이 서로 맞지 않는 구조적 결함은 확인했다.

`MSG_PK/JP/msgdata.bin` ID 614의 현재 성 문자열은 `고바야카와 `이다. 화면에 보이는
성은 다섯 글자지만 레코드에는 뒤 공백까지 있어 UTF-16 코드 유닛 수가 6이다. 기존
실행 파일은 가상 히메의 성명 전체 한도를 6으로 계산했다. 따라서 화면 생성 시
`6 - 상속 성 길이`가 0이 되고, 입력 위젯과 결정 검증 경로가 정상적인 이름 입력
여유를 갖지 못한다.

이 결함은 기존 이슈 62 패치가 해결한 한글 문자 허용 여부와 별개다. 이슈 62의 네
문자 검증 우회는 그대로 유지하고, 성명 용량을 계산하는 세 경로를 함께 보정해야 한다.

## Ghidra 정적 분석 결과

Steam JP PK 1.1.7 PC 실행 파일에서 확인한 경로는 다음과 같다.

| 역할 | RVA | 파일 오프셋 | 기존 명령 | 보정 명령 |
|---|---:|---:|---|---|
| 작명 화면 생성·입력칸 최대 길이 | `0x00E55185` | `0x00E54585` | `mov ebx, 6` | `mov ebx, 14` |
| 결정 시 성명 합계 검증 | `0x00EB4800` | `0x00EB3C00` | `mov r15d, 6` | `mov r15d, 14` |
| 입력 팝업 안내·잔여 길이 | `0x00ED6A04` | `0x00ED5E04` | `mov ebx, 6` | `mov ebx, 14` |

Steam Deck 실행 파일은 코드 배치가 달라 같은 세 명령의 파일 오프셋이 각각
`0x00E547D5`, `0x00EB4070`, `0x00ED6374`이다. 주변 제어 흐름과 피연산자를 PC
경로와 대조해 동일 기능임을 확인했다.

한도 14는 임의 확장이 아니다. 같은 실행 파일의 다른 이름 입력 경로가 14자 한도를
사용하고, 대상 복사 버퍼가 30바이트이므로 UTF-16 14자와 종결자 1개가 들어간다.
현재 번역 성 목록의 최장 길이는 7 코드 유닛이어서 14를 사용하면 최장 성에도 최소
7 코드 유닛의 이름 여유가 남는다.

## v0.94.0 패처 구현

PC 가로형·세로형, 일반·XINPUT 여섯 대상에 아래 동일 길이 패치를 누적 정적 보정으로
적용한다.

| 파일 오프셋 | 이전 바이트 | 이후 바이트 |
|---:|---|---|
| `0x00E54585` | `BB06000000` | `BB0E000000` |
| `0x00EB3C00` | `41BF06000000` | `41BF0E000000` |
| `0x00ED5E04` | `BB06000000` | `BB0E000000` |

Steam Deck에는 위에서 확인한 SD 전용 세 오프셋을 사용한다. 모든 사이트는 정확한
이전 바이트 또는 이미 적용된 이후 바이트만 허용한다. 다른 바이트가 있으면 설치를
중단한다. 적용 후 PE 체크섬과 전체 파일 SHA-256을 다시 계산하고, 설치 상태를
`0.94.0`으로 갱신한다.

기존 0.93.0 관리 설치본의 최종 해시를 업그레이드 입력으로 명시적으로 허용한다.
복구 시에는 기존 서명 번들이 만든 검증 백업을 그대로 사용하므로 순정 실행 파일로
돌아간다. 기존 이슈 62 네 사이트와 다른 정적 패치는 변경하지 않는다.

## 검증 범위

- PC 여섯 fixture에서 순정 정적 대상 생성과 최종 해시를 검증한다.
- 현재 0.93.0 최종물과 더 오래된 관리 설치 해시에서 0.94.0으로 업그레이드한다.
- 같은 보정을 두 번 적용해도 결과가 바뀌지 않는지 검사한다.
- 잘못된 선행 바이트를 거부하는지 검사한다.
- 기존 서명 Steam Deck 번들을 격리된 순정 설치본에 적용하고, 0.94.0 후처리,
  재검증, 순정 복구까지 왕복 검사한다.
- 실제 제보 저장에서 입력창 진입·이름 입력·결정·저장 후 재로드를 확인하는 런타임
  검증은 별도 항목이다. 제보자의 정확한 충돌 명령은 덤프가 없으므로 확정하지 않는다.

Steam 설치본에는 중간 빌드를 적용하지 않는다. 검증된 v0.94.0 릴리즈 후보가
완성된 뒤인 2026-08-20에만 배포용 패처 0.2.8로 적용했다. 적용 당시 게임과
런처는 종료되어 있었고 해상도는 변경하지 않았다. PC 가로형 일반·XINPUT과
Steam Deck 실행 파일은 위 고정 최종 해시와 일치하며 설치 상태의 세 릴리스
버전도 모두 `0.94.0`이다. 실제 제보 저장의 입력·결정·재로드 검증은 남아 있다.
