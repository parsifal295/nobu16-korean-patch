# v0.15.0 인물 대사 재번역 기준

## 판단 우선순위

1. 순정 Steam PC 일본어의 의미·화자 태도·상황을 기준으로 삼는다.
2. 같은 PC 레코드의 EN/SC/TC는 생략된 주어, 동적 삽입부, 다의어를 확인하는
   문맥 자료로만 사용한다.
3. 기존 한국어는 토큰·줄바꿈·실제 로딩 상태의 기준일 뿐, 새 문장의 의미
   근거로 사용하지 않는다.
4. Switch 한국어와 과거 한국어 번역 파일은 번역 판단에 사용하지 않는다.
5. 역사적 사실이나 독음이 불확실하면 자연스러워 보이는 표현으로 메우지 않고
   보류한다.

## 한국어 문체

- 화자의 지위·관계·성격을 보존하되 모든 대사를 과장된 사극체로 만들지 않는다.
- 명령·보고·독백·부부·주종 관계를 구분한다. 원문에 없는 존칭이나 비하를
  덧붙이지 않는다.
- `ございます`, `申す`처럼 명시적으로 격식이 높은 문장은 `-사옵니다`,
  `-겠사옵니다`를 사용할 수 있다. 일반 정중체에는 `-습니다`를 쓴다.
- 설명문과 시스템 알림은 간결하게 쓰고, 대사체 종결을 억지로 덧붙이지 않는다.
- 일본어 어순을 그대로 옮긴 명사 나열과 중복 주어를 피한다.

## 역사·용어

- 관직, 법명, 통칭, 유년명, 가문 관계, 지명, 전투명은 프로젝트 표기와 공신력
  있는 근거가 일치할 때만 승인한다.
- 원문의 역사적 주장과 후대의 정설이 다르더라도 대사가 인물의 믿음·선전·평가를
  말하는 장면이면 이를 사실 서술로 바꾸지 않는다.
- 사실을 확정하는 설명문은 최소 두 문맥 자료 또는 한 개의 권위 있는 직접
  근거를 확인한다. 논쟁적인 설은 단정형을 피하고 원문의 태도를 보존한다.
- 일본 고유 제도를 한국의 유사 제도명으로 바꿔치기하지 않는다. 자연스러운
  일반어가 정확하면 일반어를 쓰고, 고유성이 중요하면 음역과 설명을 조합한다.

## 동적 토큰과 레이아웃

- 이름·가문·지명·수치가 리터럴 사이에 삽입되는 레코드는 앞뒤 조사가 실제
  결합하는지 별도로 확인한다.
- ESC 태그, printf 토큰, 대괄호 런타임 토큰, C0 제어 코드는 종류와 순서를
  바꾸지 않는다.
- 현재 리터럴의 앞뒤 공백은 보존한다.
- 줄바꿈 수를 바꾸면 실게임 레이아웃 검증 전에는 승인하지 않는다.
- PK `msgev` 이벤트 대사의 912px 규칙을 `msggame`에 전용하지 않는다.

## 비표시 내부 데이터 분류

- 기계적 printable 후보라도 실제 대사·UI로 표시된다는 증거가 없고, 고립된 테스트
  블록 안에서 더미 자리표시자·글리프 격자·임의 시험값·문법 활용 시험문이 함께
  확인되면 `confirmed_non_display`로 분류할 수 있다.
- 비표시 판정은 개별 문장이 이상하다는 인상만으로 내리지 않는다. 블록 경계,
  연속 레코드의 용도, 현지화 문맥 부재처럼 서로 독립적인 구조 근거를 함께 기록한다.
- `confirmed_non_display`는 새 번역을 만들지 않고 현재 리터럴을 그대로 보존한다.
  후보 전체 좌표 감사에서는 승인된 결정 한 건으로 집계한다.

## 표기

- 문장부호는 한국어 반각 `!`, `?`를 사용한다. 여운은 원문의 강도에 따라
  `……`을 사용한다.
- 버튼·고정 UI 명칭은 현재 프로젝트의 실제 화면 표기를 따른다.
- 인명 뒤 `님`, 호칭, 관직은 문맥상 필요한 경우에만 붙인다.
- 공개 산출물에는 정식판 일본어·EN/SC/TC 문장을 넣지 않는다. 좌표·해시·새
  한국어와 검증 메타데이터만 기록한다.
