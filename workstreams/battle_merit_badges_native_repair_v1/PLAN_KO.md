# 전공 배지 native 좌표 복원 작업 계획

## 목표

현재 고해상도 군평정 아틀라스에 존재하는 한글 전공 1·2·3위 배지를
개별 RGBA sprite로 분리한다. 각 배지를 순정 고해상도 native 사각형에
복원한 뒤 정확히 1/2 축소하여 저해상도 아틀라스의 서로 다른 native
사각형에 배치한다.

고해상도 전체 아틀라스를 축소하거나 다시 배치하지 않는다. Steam 설치본은
입력으로 읽기만 하며 후보는 이 워크트리의 ignored `tmp` 아래에만 만든다.

## 고정 입력

| 역할 | 파일 | SHA-256 |
| --- | --- | --- |
| 현재 저해상도 통합본 | Steam `RES_JP/res_lang.bin` | `952B97FAE48F5D077E4663EFBE7B2975ADDBC0A521E63F9EDE373D7A77D55600` |
| 현재 고해상도 통합본 | Steam `RES_JP_PK_PORT/res_lang_pk_port1.bin` | `E2B22DFD399E87DF109947F0F98FC58D1BF360B1B54299A6BB4D2051CE53EEA5` |
| 고해상도 좌표 기준 | Steam JP 1.1.7 순정 PORT1 | `00E9C1063ED164402AA70CB770100D8AE11A92B8024F20A4F1D89F2EA1A467F7` |
| 저해상도 배치 기준 | 잘못된 전체 반축소 적용 직전 통합본 `apply_backup_001` | `49A78DAD3E796137550A1AE268018E5D54564B47AF0D72844284B266F06ED36D` |
| 저해상도 `/12` 검증 근거 | `steam_jp_military_overlay_v1/run_b` 후보 | `BE16494D8881143FA525C4A6743BC9D47044B661D3C0000DBA4EC12C9E25809C` |

저해상도 배치 기준의 `/12` payload는 검증 근거 후보의 payload
`0E76BA383BF4AC6D50F47F0F5B9571AF9CEB2A872063095749F4A296D3D51FD6`
와 동일하다. 군평정 제목, 승리·패배, 버튼 안내의 기존 한글 오버레이를
포함하고 전공 배지는 순정 native 위치에 보존한다.
현재 저해상도 `/12`는 고해상도 전체 반축소로 패킹이 훼손되었으므로
배치 기준으로 사용하지 않는다.

기존 저해상도 기준에는 버튼 안내 오른쪽의 일본어 잔여 픽셀이 남아 있다.
이는 이번 전공 배지 파손과 별개의 선행 문제이며, 이 작업은 그 영역을
변경하거나 전체 저해상도 화면이 합격했다고 주장하지 않는다.

## 배지별 좌표 매핑

고해상도 소스·목표는 알파 임계값 32의 연결 성분 bbox다. 저해상도 목표는
순정 native 연결 성분 bbox이며, 기존 한글 오버레이의 BC3 재인코딩본에서는
1위의 약한 위쪽 알파 2px가 임계값 아래로 내려가지만 같은 목표 안에 있다.

| 배지 | 현재 고해상도 소스 | 순정 고해상도 목표 | 저해상도 목표 |
| --- | --- | --- | --- |
| 전공 1위 | `[2984,383,3364,459]` (`380×76`) | `[2960,400,3344,480]` (`384×80`) | `[1082,254,1274,294]` (`192×40`) |
| 전공 2위 | `[3002,485,3346,549]` (`344×64`) | `[2982,500,3322,572]` (`340×72`) | `[1297,256,1467,292]` (`170×36`) |
| 전공 3위 | `[3693,625,4029,688]` (`336×63`) | `[3686,644,4026,716]` (`340×72`) | `[1501,256,1671,292]` (`170×36`) |

각 저해상도 목표의 크기는 대응하는 순정 고해상도 목표의 정확한 1/2이다.
캔버스 좌표는 1/2 관계가 아니므로 축소한 sprite를 저해상도 고유 좌표에
개별 배치한다.

## 실행 순서

1. 네 입력의 크기와 SHA-256을 고정값과 대조한다.
2. 고해상도 현재본 `/17/0`과 순정 `/17/0`이 PC BC3 `4096×1024`,
   resource id `58`, texture 1개인지 확인한다.
3. 현재 고해상도 소스 사각형에서 배지별 RGBA를 추출한다.
4. premultiplied-alpha Lanczos3로 각 배지를 순정 고해상도 목표 크기에
   맞추고, 소스·목표 합집합을 비운 뒤 목표 좌표에 붙인다.
5. 합집합을 덮는 BC3 블록만 재인코딩하여 현재 고해상도 통합본의 `/17`
   payload를 교체한다.
6. 저해상도 검증 후보 `/12/0`을 배치 기준으로 삼는다. 4개의 기존 안전
   한글 오버레이와 나머지 native 패킹을 그대로 보존한다.
7. 4단계의 복원된 고해상도 배지를 각각 정확히 1/2 축소하여 저해상도
   목표 좌표에 붙이고, 목표를 덮는 BC3 블록만 재인코딩한다.
8. 저해상도 payload를 현재 저해상도 통합본 `/12/0`에 넣는다. `/12`
   밖의 모든 outer는 현재 설치본과 byte-identical하게 보존한다.
9. 후보 두 파일, 배지별 PNG, before/after contact sheet, 구조·해시·블록
   검증 보고서를 ignored `tmp/battle_merit_badges_native_repair_v1`에 쓴다.

## 사전 검수 게이트

- [x] 고해상도 소스와 목표 사각형이 서로 다른 배지나 작은 버튼 sprite를
      포함하지 않는다.
- [x] 고해상도 목표 크기의 정확한 1/2이 저해상도 목표 크기다.
- [x] 고해상도는 `/17`, 저해상도는 `/12`만 바꾼다.
- [x] 고해상도에서 허용 합집합 밖 BC3 블록은 현재 통합본과 byte-identical하다.
- [x] 저해상도에서 배지 블록 밖 payload는 검증된 저해상도 배치 기준과
      byte-identical하다.
- [x] G1T payload 앞뒤 바이트, resource id, texture 수·형식·크기가 유지된다.
- [x] 후보와 QA 산출물은 ignored `tmp` 아래에만 생성한다.
- [x] Steam 적용, 릴리스 파일 변경, Git 커밋·푸시는 하지 않는다.

## 실행 후 합격 기준

1. 후보 재파싱과 LINK/LZ4/G1T round-trip이 모두 PASS다.
2. 고해상도 후보의 세 배지 알파 bbox가 각각의 순정 목표 안에 있다.
3. 저해상도 후보의 세 배지 알파 bbox가 각각의 native 목표 안에 있다.
4. 세 저해상도 배지는 복원된 고해상도 배지의 개별 1/2 축소본이다.
5. 고해상도 비허용 블록, 저해상도 배치 기준의 비배지 블록, 양쪽
   비대상 outer가 byte-identical하다.
6. contact sheet에서 배지 세 개가 잘리지 않고 서로의 영역과 겹치지 않는다.
7. 실게임 합격 판정은 별도 릴리스 승인 후 Steam 적용 직전에만 수행한다.
   해상도를 선택한 뒤 `NOBU16PK.exe`를 완전히 종료·재실행하고 결과에
   선택 해상도와 완전 재시작 여부를 기록한다.

## 사전 검수 결과

`PASS`

- 알파 임계값 32 연결 성분에서 세 고해상도 소스와 세 순정 고해상도 목표를
  각각 독립 성분으로 재확인했다. 저해상도 기준의 각 최대 배지 성분은
  대응 native 목표 안에 포함된다.
- 목표 크기는 `384×80 → 192×40`, `340×72 → 170×36`,
  `340×72 → 170×36`으로 정확히 2:1이다.
- 저해상도 배치 기준은 잘못된 `low-from-high` 빌드의 실제 입력 백업이며,
  그 빌드 보고서에서 `/12` 입력 payload가 위 검증 근거와 일치한다.
- 구현은 기존 LINK/G1T 재조립 함수와 선택 BC3 block 인코더만 사용하므로
  비대상 outer·slot·payload 영역에 대한 byte 보존 게이트를 적용할 수 있다.
- 위 일본어 잔여 픽셀은 시각 검수에서 확인했으며 이번 후보의 합격 범위에서
  명시적으로 제외했다.
