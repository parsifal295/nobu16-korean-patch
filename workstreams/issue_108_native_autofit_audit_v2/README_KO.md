# 이슈 #108 성주명 native auto-fit 최종 감사

이 문서는 내부 검증 기록이다. 결론은 **신규 바이너리 패치 없음**이다. 기존 `issue_108_castle_lord_name_fit_v1` 및 후속 patch019 기반 후보는 폐기하며 Steam 배포 입력으로 사용하지 않는다.

## 결론 근거

- 실제 대상은 지행 요약 패널의 `x=121, y=437, h=28, style=1` 성주명 객체다. 런타임 대상 문자열은 `호소카와 다다오키`(UTF-16 9 code units)이고 객체의 `+0x5C` 폭은 이미 고정 `168px`였다. 따라서 `width > 168` 조건으로 만든 후보는 대상에서 동작하지 않는다.
- 엔진은 `0x1409629B0`에서 문자열을 직접 계측하고, 대상에 `XMM0=0.7058823704719543`을 반환했다. 호출자는 이를 `XMM11`로 넘겨 후단 렌더 스케일에 사용한다. `+0x8C=0`이라 native auto-fit 비활성 조건에도 걸리지 않는다.
- 현재 patch012 공통 훅은 대상 프로필을 변형하지 않고 원래 렌더 경로로 복귀하며, patch019 우측 cap 훅은 별도 지점이다. 따라서 현재 정적 패치 체인은 native auto-fit을 보존한다.
- clean 화면의 성주명 잉크는 `x=163..379`, 성 아이콘은 `x=397..426`, 수량은 `x=435`부터다. 이름/아이콘 겹침은 `0px`, 빈 간격은 `17px`이며 GitHub 원본도 겹침 `0px`, 간격 `23px`다. 여기에 별도 길이 기반 스케일을 곱하면 과압축 회귀 위험이 생긴다.
- 1920×1080으로 바꾸고 게임을 완전히 종료·재실행한 후에도 같은 긴 이름이 네이티브 자동 맞춤으로 `238px→168px` 축소됐다. 이름·성 아이콘·수치의 겹침은 `0px`였고 짧은 이름은 축소되지 않았다.

## 복원 및 무변경 확인

- 두 임시 telemetry 훅(`RVA 0x973ED5`, `0x973F1D`)은 원본 바이트로 복원되었고, 실행 중 프로세스에서 재독해 일치를 확인했다.
- remote cave는 0.1초 drain 뒤 `VirtualFreeEx(..., MEM_RELEASE)` 정리 경로를 거쳤다. 대상 객체 주소를 포함한 probe 고유 서명을 committed RWX 영역에서 재검색한 결과 `0건`이었다.
- telemetry는 프로세스 메모리에만 잠시 적용했다. Steam 파일 쓰기는 없었고 최종 SHA-256은 다음과 같다.
  - `NOBU16PK.exe`: `8453B235CD79F9D8621A287E40CB6DACDA86C00FBA4F860D0989E83E4689B43E`
  - `NOBU16PK_XINPUT.exe`: `F4882AC42011EB6AF9139B3327E88C7CF2F0F1A8CDCFCB1823B9465829F2C034`
